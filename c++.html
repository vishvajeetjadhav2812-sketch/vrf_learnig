Section 01

Introduction to C++

C++ is a general-purpose, compiled, multi-paradigm programming language created by Bjarne Stroustrup at Bell Labs, first released in 1985 as an extension of C ("C with Classes"). It combines low-level memory control with high-level abstractions, making it a dominant choice for performance-critical systems.

Evolution of C++

Key Features

  • High Performance — compiles directly to native machine code with minimal runtime overhead.
  • Low-Level Memory Control — manual allocation via pointers, alongside modern RAII-based safety.
  • Multi-Paradigm — supports procedural, object-oriented, generic, and functional programming styles.
  • Zero-Cost Abstractions — high-level constructs (templates, classes) compile down with no extra runtime cost versus hand-written low-level code.
Section 02

Compilation & Execution Model

Unlike interpreted languages, C++ source code is transformed into a native executable through a multi-stage build pipeline before it ever runs:

Source (.cpp / .h) → Preprocessor (expands macros, #include) → Compiler (g++, clang++, MSVC — produces assembly) → Assembler (produces object files .o/.obj) → Linker (resolves symbols, links libraries) → Executable Machine Code (.exe / binary)

Control Flow & Loops

control-flow.cpp 
#include <iostream>
using namespace std;

int main() {
    int score = 78;

    // if-else
    if (score >= 90) cout << "Grade: A\n";
    else if (score >= 75) cout << "Grade: B\n";
    else cout << "Grade: C\n";

    // switch-case
    int day = 3;
    switch (day) {
        case 1: cout << "Mon\n"; break;
        case 3: cout << "Wed\n"; break;
        default: cout << "Other\n";
    }

    // classic for loop
    for (int i = 0; i < 3; ++i) cout << "i=" << i << " ";
    cout << endl;

    // range-based for (C++11)
    int nums[] = {10, 20, 30};
    for (int n : nums) cout << n << " ";
    cout << endl;

    // while / do-while
    int count = 0;
    while (count < 2) { cout << "while "; count++; }
    cout << endl;

    return 0;
}
Output

Section 04

Functions, Pointers & Memory Management

Function Overloading & Parameter Passing

functions.cpp 
#include <iostream>
using namespace std;

// function overloading — same name, different signatures
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }

// pass-by-value: copy is modified, original stays same
void byValue(int x) { x += 10; }

// pass-by-reference: modifies the original variable
void byReference(int& x) { x += 10; }

// pass-by-pointer: modifies via address
void byPointer(int* x) { *x += 10; }

int main() {
    cout << add(3, 4) << " " << add(2.5, 1.5) << endl;

    int a = 5;
    byValue(a);     cout << "After byValue: " << a << endl;
    byReference(a); cout << "After byReference: " << a << endl;
    byPointer(&a);  cout << "After byPointer: " << a << endl;
    return 0;
}
Output
7 4 After byValue: 5 After byReference: 15 After byPointer: 25

Dynamic Memory Allocation

dynamic-memory.cpp 
#include <iostream>
using namespace std;

int main() {
    int* single = new int(42);      // allocate single int on heap
    int* arr = new int[5];      // allocate array on heap

    cout << *single << endl;

    delete single;         // free single object
    delete[] arr;          // free array — must match new[] with delete[]

    int* danger = nullptr;   // null pointer — safer than uninitialized pointer
    if (danger == nullptr) cout << "Pointer is null, safe to check.\n";
    return 0;
}
Output
42 Pointer is null, safe to check.
Dangling pointer risk: after delete single;, the pointer still holds the old address. Dereferencing it is undefined behavior — always set freed pointers to nullptr.

Smart Pointers (Modern C++11)

Smart pointers wrap raw pointers in RAII objects that automatically release memory, eliminating most manual delete calls and memory leaks.

std::unique_ptr — exclusive ownership+

Owns a resource exclusively; cannot be copied, only moved. Automatically deleted when it goes out of scope.

#include <memory>
#include <iostream>
using namespace std;

int main() {
    unique_ptr<int> ptr = make_unique<int>(100);
    cout << *ptr << endl;
    // unique_ptr<int> ptr2 = ptr;      // ERROR: cannot copy
    unique_ptr<int> ptr2 = std::move(ptr); // OK: ownership transferred
    return 0;
}
std::shared_ptr — shared ownership+

Multiple shared_ptr instances can own the same resource via a reference count; memory frees when the count hits zero.

#include <memory>
#include <iostream>
using namespace std;

int main() {
    shared_ptr<int> a = make_shared<int>(10);
    shared_ptr<int> b = a;   // shared ownership, count = 2
    cout << "Use count: " << a.use_count() << endl;
    return 0;
}
std::weak_ptr — non-owning reference+

Observes a shared_ptr-managed object without increasing its reference count — used to break circular reference cycles.

#include <memory>
#include <iostream>
using namespace std;

int main() {
    shared_ptr<int> sp = make_shared<int>(7);
    weak_ptr<int> wp = sp;     // does not increase use_count
    if (auto locked = wp.lock()) {
        cout << "Value still alive: " << *locked << endl;
    }
    return 0;
}

Object-Oriented Programming in C++

Classes, Objects & Access Specifiers

class-basics.cpp 
#include <iostream>
using namespace std;

class Account {
private:
    double balance;         // hidden from outside
public:
    Account(double initial) { balance = initial; }   // parameterized constructor
    Account() : balance(0) {}                       // default constructor
    Account(const Account& other) { balance = other.balance; } // copy constructor
    ~Account() { cout << "Account destroyed\n"; }    // destructor

    void deposit(double amt) { balance += amt; }
    double getBalance() const { return balance; }
};

int main() {
    Account acc(500.0);
    acc.deposit(250);
    cout << "Balance: " << acc.getBalance() << endl;
    return 0;
}
Output
Balance: 750 Account destroyed

The Four Pillars of OOP

1. Encapsulation — bundling data and methods together while restricting direct access via private/protected, exposing only what's needed through public methods (seen in the Account class above).

2. Inheritance — a class acquires properties of another. C++ supports single, multiple, and virtual inheritance.

class Animal {
public:
    void eat() { std::cout << "Eating...\n"; }
};

class Dog : public Animal {   // single inheritance
public:
    void bark() { std::cout << "Barking...\n"; }
};

// Virtual inheritance solves the "diamond problem" in multiple inheritance
class Base { public: int value = 1; };
class Left : virtual public Base {};
class Right : virtual public Base {};
class Diamond : public Left, public Right {}; // only one Base subobject

3. Polymorphism — compile-time (function/operator overloading) vs runtime (virtual functions with VTables).

#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() { cout << "Drawing a shape\n"; }  // virtual enables runtime dispatch
    virtual ~Shape() {}
};
class Circle : public Shape {
public:
    void draw() override { cout << "Drawing a circle\n"; }
};

int main() {
    Shape* s = new Circle();
    s->draw();   // resolved at runtime via VTable -> "Drawing a circle"
    delete s;
    return 0;
}
Output
Drawing a circle

4. Abstraction — exposing only essential behavior through pure virtual functions, forming abstract base classes/interfaces.

class Drawable {
public:
    virtual void render() = 0;   // pure virtual — makes this class abstract
};

class Square : public Drawable {
public:
    void render() override { std::cout << "Rendering square\n"; }
};
// Drawable d;  // ERROR: cannot instantiate an abstract class

Modern Advanced C++ Concepts

Move Semantics & Rvalue References

Copy vs Move Constructor+

std::move converts an lvalue into an rvalue reference, enabling the move constructor to "steal" resources instead of deep-copying — a major performance win for heap-allocated data.

#include <iostream>
#include <utility>
using namespace std;

class Buffer {
    int* data;
public:
    Buffer(int size) : data(new int[size]) { cout << "Constructed\n"; }

    // Copy constructor — deep copy (expensive)
    Buffer(const Buffer& other) { cout << "Copied (expensive)\n"; }

    // Move constructor — steals the pointer, no copy (cheap)
    Buffer(Buffer&& other) noexcept : data(other.data) {
        other.data = nullptr;
        cout << "Moved (cheap)\n";
    }
    ~Buffer() { delete[] data; }
};

int main() {
    Buffer a(100);
    Buffer b = std::move(a);   // invokes move constructor
    return 0;
}
Output
Constructed Moved (cheap)

Concurrency & Multithreading

threading.cpp 
#include <iostream>
#include <thread>
#include <mutex>
#include <future>
using namespace std;

mutex mtx;
int counter = 0;

void increment() {
    lock_guard<mutex> lock(mtx);   // RAII-based locking
    counter++;
}

int computeSquare(int x) { return x * x; }

int main() {
    thread t1(increment);
    thread t2(increment);
    t1.join(); t2.join();
    cout << "Counter: " << counter << endl;

    auto fut = std::async(std::launch::async, computeSquare, 9); // runs async
    cout << "Square: " << fut.get() << endl;
    return 0;
}
Output
Counter: 2 Square: 81

C++20 Highlights

  • Concepts & Constraints — constrain template parameters with readable, named requirements instead of cryptic SFINAE.
  • Ranges — compose lazy view pipelines over containers (std::ranges::views).
  • Coroutines — native co_await/co_yield support for asynchronous and generator-style code.
  • Modules — replace header files with faster-compiling, encapsulated import units.
concepts.cpp 
#include <concepts>
#include <iostream>

template <typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

template <Numeric T>
T square(T x) { return x * x; }

int main() {
    std::cout << square(6) << std::endl; // OK — int satisfies Numeric
    // square("text");            // compile error: constraint not satisfied
    return 0;
}
Output
36
