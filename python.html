Python, from indentation to interfaces.

Python's whole pitch is that code should read like plain instructions. That readability is also what makes it forgiving to learn — this guide moves through the language in the order you'll actually use it: syntax, data, functions, then objects and the standard library once you're comfortable enough to reach for them.

Level Beginner → Intermediate Reading time ~40 min Python version 3.11+ examples

01 What is Python?

A high-level, general-purpose language designed around one core value: code is read far more often than it's written.

Python was created by Guido van Rossum and first released in 1991, named after Monty Python's Flying Circus rather than the snake. Its defining trait is that indentation isn't just style — it's syntax. Where other languages use curly braces to mark a block of code, Python uses whitespace, which forces every Python program into a consistent, readable shape.

Core features

Interpreted

Code runs line by line through an interpreter rather than being compiled to a standalone binary first.

Dynamically Typed

You never declare a variable's type — it's inferred at runtime, and can even change as the program runs.

High-Level

Memory management and low-level details are handled for you, so code focuses on logic, not housekeeping.

Multi-paradigm

Supports procedural, object-oriented, and functional styles — pick whichever fits the problem.

Batteries-Included

The standard library ships with modules for file I/O, networking, math, dates, and more — no setup required.

Cross-Platform

The same source runs on Windows, macOS, and Linux wherever a Python interpreter is installed.

02 Python 2 vs 3, and How Python Runs

A brief note on history, then the pipeline your code actually travels through.

Python 2 reached end-of-life on January 1, 2020. All new work should target Python 3 — string handling, integer division, and print syntax all changed between the two, and Python 2 no longer receives security updates. If you see print "text" without parentheses anywhere, that's Python 2 code.

Source code → Bytecode → PVM

1. Source (.py)

The human-readable code you write, saved in a .py file.

2. Bytecode (.pyc)

The interpreter compiles your source into a lower-level, platform-independent instruction set.

3. PVM

The Python Virtual Machine executes that bytecode line by line — this is the interpreter actually "running."

This is why Python is called interpreted rather than compiled in the C/Java sense: there's no separate build step producing a standalone executable — the PVM reads and runs the bytecode every time you execute the script.

03 Basic Syntax & Indentation

Whitespace is not cosmetic in Python — it's how blocks of code are defined.

indentation.py
def check_age(age):
    if age >= 18:
        print("You can vote.")      # indented 4 spaces — inside the if
    else:
        print("Not yet.")            # same rule applies here
    print("Check complete.")          # back at function level — always runs
  • No braces, no semicolons. A colon : opens a block; the next line's indentation defines what's inside it.
  • Be consistent. Mixing tabs and spaces raises an IndentationError — most style guides recommend 4 spaces.
  • Comments start with # and run to the end of the line.
  • Everything in Python — functions, numbers, even modules — is an object.

05 Type Casting & Input / Output

Converting between types explicitly, and getting data in and out of a program.

io_and_casting.py
name = input("What's your name? ")       # input() always returns a string
age_text = input("What's your age? ")
age = int(age_text)                        # explicit cast: str -> int
 
print(f"Hi {name}, in 5 years you'll be {age + 5}.")  # f-string

The f before the string turns it into an f-string — anything inside {} is evaluated and inserted directly. Common casts: int(), float(), str(), bool().

06 Operators

Python adds two operator families most languages don't have: is for identity and in for membership.

Arithmetic

+ - * / // % ** — // is floor division, ** is exponentiation.

Comparison

== != > < >= <= — always return a bool.

Logical

and or not — written as words, not symbols.

Bitwise

& | ^ ~ << >> — operate on the binary representation of integers.

Assignment

= += -= *= /= — compound forms combine an operation with assignment.

Identity & Membership

is checks if two names point to the same object; in checks membership in a sequence.

is_vs_equals.py
a = [1, 2, 3]
b = [1, 2, 3]
 
print(a == b)   # True  -- same contents
print(a is b)    # False -- different objects in memory
print(3 in a)     # True  -- membership check

08 Two Complete Programs

The smallest possible Python program, and an interactive guessing game that ties loops, conditionals, and I/O together.

Hello, World

hello_world.py
print("Hello, World!")

That's the entire program — no class, no main function required. Python executes top-level statements directly.

Number Guessing Game

guessing_game.py
import random
 
secret = random.randint(1, 20)
attempts = 0
 
print("I'm thinking of a number between 1 and 20.")
 
while True:
    guess = int(input("Your guess: "))
    attempts += 1
 
    if guess < secret:
        print("Too low.")
    elif guess > secret:
        print("Too high.")
    else:
        print(f"Correct! You got it in {attempts} tries.")
        break

10 List & Dictionary Comprehensions

A one-line way to build a new collection from an existing one — arguably the most "Pythonic" idiom in the language.

comprehensions.py
# list comprehension: [expression for item in iterable if condition]
squares = [n**2 for n in range(6)]
# [0, 1, 4, 9, 16, 25]
 
evens = [n for n in range(10) if n % 2 == 0]
# [0, 2, 4, 6, 8]
 
# dict comprehension: {key_expr: value_expr for item in iterable}
name_lengths = {name: len(name) for name in ["Ada", "Grace"]}
# {'Ada': 3, 'Grace': 5}
A comprehension is equivalent to a for loop with an .append() — just faster to write, and often faster to run.

11 Functions

Reusable blocks of logic, with flexible ways to accept arguments.

functions.py
def greet(name, greeting="Hello"):    # default argument
    return f"{greeting}, {name}!"
 
print(greet("Ada"))                  # "Hello, Ada!"
print(greet("Ada", "Hi"))            # "Hi, Ada!"
 
def total(*args):                     # *args -- any number of positional args, as a tuple
    return sum(args)
 
print(total(1, 2, 3, 4))            # 10
 
def build_profile(**kwargs):          # **kwargs -- any number of named args, as a dict
    return kwargs
 
print(build_profile(name="Ada", age=36))
# {'name': 'Ada', 'age': 36}

12 Lambda, map(), filter() & reduce()

Small, anonymous functions and the tools built to apply them across a collection.

functional.py
from functools import reduce
 
square = lambda x: x ** 2          # anonymous, single-expression function
print(square(5))                  # 25
 
nums = [1, 2, 3, 4, 5]
 
doubled = list(map(lambda n: n * 2, nums))
# [2, 4, 6, 8, 10]
 
evens = list(filter(lambda n: n % 2 == 0, nums))
# [2, 4]
 
total = reduce(lambda acc, n: acc + n, nums)
# 15 -- collapses the list to a single value

map() transforms every item, filter() keeps only items matching a condition, and reduce() (from functools) folds the whole sequence into one result.

14 Classes & Objects

self is Python's explicit way of saying "this particular object" — every instance method takes it as the first parameter.

classes.py
class Car:
    wheels = 4                          # class variable -- shared by every instance
 
    def __init__(self, color, speed=0):    # constructor
        self.color = color               # instance variable -- unique per object
        self.speed = speed
 
    def accelerate(self, amount):
        self.speed += amount
        print(f"{self.color} car now going {self.speed} km/h")
 
mine = Car("Red")                    # object #1
mine.accelerate(40)
 
yours = Car("Blue", speed=10)        # object #2, independent state
yours.accelerate(15)
wheels is a class variable — every Car shares one copy. color and speed are instance variables — each object gets its own.

15 Encapsulation

Python doesn't have a true "private" keyword — it uses naming conventions and name mangling instead, backed by a trust-based culture.

public

self.name — freely accessible from anywhere.

_protected

Single underscore — a convention meaning "internal use," but still accessible.

__private

Double underscore — triggers name mangling to _ClassName__attr, discouraging accidental access.

encapsulation.py
class BankAccount:
    def __init__(self, balance=0):
        self.__balance = balance        # name-mangled -- discourages direct access
 
    @property
    def balance(self):                  # getter -- accessed like an attribute, no ()
        return self.__balance
 
    @balance.setter
    def balance(self, amount):          # setter -- runs validation on assignment
        if amount < 0:
            raise ValueError("Balance can't go negative")
        self.__balance = amount
 
acct = BankAccount(100)
acct.balance = 150          # calls the setter
print(acct.balance)     # calls the getter -- 150

16 Inheritance

A class can build on another class's behavior — and unlike Java, Python allows inheriting from more than one class at once.

Single

One parent, one child. class Dog(Animal):

Multiple

A class inherits from more than one parent at once. class Robot(Machine, Animal):

Multilevel

A chain of inheritance. class Puppy(Dog): where Dog already extends Animal.

inheritance.py
class Animal:
    def __init__(self, name):
        self.name = name
 
    def eat(self):
        print(f"{self.name} is eating.")
 
class Dog(Animal):                    # single inheritance
    def __init__(self, name, breed):
        super().__init__(name)         # calls Animal's constructor
        self.breed = breed
 
    def bark(self):
        print(f"{self.name} says Woof!")
 
rex = Dog("Rex", "Labrador")
rex.eat()      # inherited from Animal
rex.bark()     # defined on Dog
super() gives you access to the parent class's methods without naming the parent directly — useful for calling the parent's __init__ before adding subclass-specific setup.

17 Polymorphism

Python leans on duck typing more than formal interfaces: "if it walks like a duck and quacks like a duck, treat it like a duck."

A subclass redefines a method it inherited, replacing the parent's version when called on that subclass.

overriding.py
class Animal:
    def speak(self):
        print("Some generic animal sound")
 
class Dog(Animal):
    def speak(self):             # same name, overrides the parent
        print("Woof!")
 
for creature in [Animal(), Dog()]:
    creature.speak()      # each calls its own version

Python doesn't check an object's type before calling a method — it just tries. If the object has the method, it works, regardless of what class it belongs to.

duck_typing.py
class Duck:
    def sound(self):
        return "Quack"
 
class Person:
    def sound(self):               # unrelated class, same method name
        return "I'm quacking like a duck!"
 
def make_it_quack(thing):        # no type check -- just calls .sound()
    print(thing.sound())
 
make_it_quack(Duck())
make_it_quack(Person())

18 Abstract Base Classes

The abc module lets Python enforce a contract when duck typing alone isn't strict enough.

abstract_base.py
from abc import ABC, abstractmethod
 
class Shape(ABC):                     # inherits from ABC
    @abstractmethod
    def area(self):                    # no implementation -- subclasses must provide one
        pass
 
class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
 
    def area(self):
        return 3.14159 * self.radius ** 2
 
# Shape()        -> TypeError: can't instantiate an abstract class
c = Circle(3)
print(c.area())
Trying to instantiate Shape directly raises a TypeError — and any subclass that skips implementing area() will too. This is Python's closest equivalent to Java's abstract classes.

19 Exception Handling

Anticipating failure gracefully, with a fuller set of blocks than most languages offer.

exceptions.py
class NegativeAmountError(Exception):    # custom exception
    pass
 
def withdraw(balance, amount):
    if amount < 0:
        raise NegativeAmountError("Amount can't be negative")
    return balance - amount
 
try:
    result = withdraw(100, -10)
except NegativeAmountError as e:
    print(f"Caught: {e}")
except Exception as e:
    print(f"Unexpected error: {e}")
else:
    print(f"Success, new balance: {result}")   # runs only if no exception occurred
finally:
    print("Withdrawal attempt finished.")          # always runs
BlockRuns when
tryAlways — wraps the risky code
exceptOnly if a matching exception is raised
elseOnly if no exception occurred
finallyAlways — regardless of what happened, for cleanup

20 File Handling

The with statement guarantees a file gets closed, even if an error interrupts the code inside it.

file_handling.py
# writing to a file
with open("notes.txt", "w") as file:
    file.write("Python makes file handling simple.\n")
 
# reading it back
with open("notes.txt", "r") as file:
    contents = file.read()
    print(contents)
 
# file is automatically closed here, even if an exception happened above

This pattern is called a context manager. Common modes: "r" read, "w" write (overwrites), "a" append, "r+" read and write.

21 Decorators & Generators

Two features that make Python code more expressive: wrapping a function's behavior, and lazily producing a sequence of values.

Decorators

decorators.py
import time
 
def timer(func):                    # a decorator: a function that wraps another function
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.4f}s")
        return result
    return wrapper
 
@timer                              # applies timer() to slow_square automatically
def slow_square(n):
    time.sleep(0.5)
    return n * n
 
slow_square(4)

Generators

generators.py
def count_up_to(limit):
    n = 1
    while n <= limit:
        yield n              # pauses here, returns n, resumes on next call
        n += 1
 
for number in count_up_to(5):
    print(number)          # 1 2 3 4 5 -- values produced one at a time, not all at once
A generator never builds the whole sequence in memory — yield hands back one value at a time, which matters a lot when the sequence is huge or infinite.

22 Common Questions

A few things almost everyone asks in their first week with Python.

Python uses indentation instead of braces to define code blocks, so inconsistent spacing isn't just ugly — it's a syntax error. Stick to 4 spaces per level and most editors will handle it automatically.
Use a list when the collection might change — adding, removing, reordering items. Use a tuple for fixed data, like coordinates or a function returning multiple values, since it's slightly faster and can't be accidentally modified.
Compared to compiled languages like C or Rust, yes, for raw CPU-bound loops. In practice most Python programs spend their time waiting on I/O or calling into fast C-based libraries (NumPy, pandas), so the difference matters less than it sounds.
The @dataclass decorator (from the dataclasses module) auto-generates __init__, __repr__, and __eq__ for classes that are mostly just holding data, saving you the boilerplate this guide wrote out by hand.
