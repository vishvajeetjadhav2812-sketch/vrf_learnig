Java, from public static void main to polymorphism.

Java has run on billions of devices for three decades because it made one unglamorous promise and kept it: write your code once, and it runs anywhere a JVM does. This guide walks through the language in the order most people actually need it — syntax first, objects second, the standard library once you're dangerous enough to use it.

Level Beginner → Intermediate Reading time ~35 min Java version 17+ examples

01 What is Java?

A general-purpose, class-based, object-oriented language designed to have as few implementation dependencies as possible.

Java was released by Sun Microsystems in 1995, built by a team led by James Gosling under the codename "Oak." The design goal was portability: code compiled once should run on any device with a Java Virtual Machine, regardless of the underlying hardware or operating system. That single idea — "Write Once, Run Anywhere" (WORA) — is why Java ended up inside everything from Android phones to bank mainframes to the Mars rovers' ground software.

Core features

Platform Independent

Source code compiles to bytecode (.class files), not machine code. Any JVM can run that bytecode.

Simple

Dropped manual pointer arithmetic and operator overloading from C++, keeping the syntax approachable.

Secure

No explicit pointers, and the bytecode verifier checks code before it runs, reducing memory-corruption exploits.

Robust

Strong compile-time type checking plus runtime exception handling catches errors before they become crashes.

Multithreaded

Built-in support for concurrent execution, letting a program perform several tasks at once.

Architecture-Neutral

The bytecode format has no dependency on any particular CPU architecture.

02 JDK vs JRE vs JVM

Three acronyms that trip up every beginner at least once. Here's the relationship: the JDK contains the JRE, and the JRE contains the JVM.

TermFull formWhat it's forWho needs it
JVM Java Virtual Machine Executes bytecode; handles memory management and garbage collection Anyone running a Java program
JRE Java Runtime Environment JVM + core class libraries needed to run compiled Java apps End users running Java software
JDK Java Development Kit JRE + compiler (javac), debugger, and other dev tools Developers writing Java code
Think of it as nesting dolls: JDK ⊃ JRE ⊃ JVM. If you're writing code, install the JDK — it already includes the other two.

03 Basic Syntax & Program Structure

Every Java program lives inside a class, and execution starts from a fixed entry point.

Structure.java
public class Structure {
 
    // the JVM looks for exactly this method signature to start
    public static void main(String[] args) {
        System.out.println("Program starts here.");
    }
}
  • Class name = file name. A public class Structure must live in Structure.java.
  • main() is the entry point. It must be public static void main(String[] args) exactly.
  • Statements end in semicolons, and blocks are scoped with curly braces.
  • Java is case-sensitive — myVar and MyVar are different identifiers.

Everything else — String, arrays, classes, interfaces — is a reference type. Instead of holding the value directly, the variable holds a reference to an object on the heap.

Variables.java
String name = "Ada";              // reference type
int[] scores = {88, 92, 79};   // array, also a reference type
int attempts = 3;              // primitive type

05 Operators

Four families cover almost everything you'll write day to day.

Arithmetic

+ - * / % — the modulus % returns a division's remainder, useful for even/odd checks and wrapping indices.

Relational

== != > < >= <= — always return a boolean. For comparing object content (like two Strings), use .equals() instead of ==.

Logical

&& || ! — && and || short-circuit, skipping the right side once the result is already known.

Assignment

= += -= *= /= — compound assignment operators combine a calculation with the assignment in one step.

06 Control Statements

Branching and looping constructs that decide what runs, and how many times.

If-Else & Switch

Branching.java
int score = 76;
 
if (score >= 90) {
    System.out.println("Grade: A");
} else if (score >= 75) {
    System.out.println("Grade: B");
} else {
    System.out.println("Grade: C or below");
}
 
switch (Integer.valueOf(score / 10)) {
    case 10, 9 -> System.out.println("Excellent");
    case 8, 7 -> System.out.println("Solid");
    default -> System.out.println("Keep practicing");
}

For, While & Do-While

Loops.java
// runs a known number of times
for (int i = 1; i <= 5; i++) {
    System.out.println("For-loop tick " + i);
}
 
// runs while a condition holds; may run zero times
int fuel = 3;
while (fuel > 0) {
    System.out.println("Fuel remaining: " + fuel);
    fuel--;
}
 
// runs the body at least once, then checks the condition
int attempt = 0;
do {
    attempt++;
    System.out.println("Attempt #" + attempt);
} while (attempt < 1);

07 Two Complete Programs

The two programs everyone writes first: the smallest possible Java program, and a loop-driven calculator.

Hello, World

HelloWorld.java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Simple Calculator with a Menu Loop

Calculator.java
import java.util.Scanner;
 
public class Calculator {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        boolean keepGoing = true;
 
        while (keepGoing) {
            System.out.println("\nEnter two numbers and an operator (+ - * /), or 'q' to quit:");
            String input = sc.nextLine();
 
            if (input.equalsIgnoreCase("q")) {
                keepGoing = false;
                continue;
            }
 
            String[] parts = input.split(" ");
            double a = Double.parseDouble(parts[0]);
            double b = Double.parseDouble(parts[2]);
            double result = switch (parts[1]) {
                case "+" -> a + b;
                case "-" -> a - b;
                case "*" -> a * b;
                case "/" -> a / b;
                default -> { throw new IllegalArgumentException("Unknown operator"); }
            };
            System.out.println("Result: " + result);
        }
        sc.close();
    }
}
Try it: type 12 * 4 and it should print Result: 48.0.

08 Class & Object

A class is a blueprint; an object is a specific thing built from that blueprint.

Think of Car as a class: it defines that every car has a color, a speed, and can accelerate. An object is one particular car built from that blueprint — a red one currently going 40 km/h. You can create as many objects from one class as you need, each with its own state.

Car.java
public class Car {
    String color;
    int speed;
 
    void accelerate(int amount) {
        speed += amount;
        System.out.println(color + " car now going " + speed + " km/h");
    }
 
    public static void main(String[] args) {
        Car mine = new Car();      // object #1
        mine.color = "Red";
        mine.accelerate(40);
 
        Car yours = new Car();     // object #2, independent state
        yours.color = "Blue";
        yours.accelerate(15);
    }
}

09 Encapsulation

Bundling data with the methods that operate on it, and hiding the data behind a controlled interface.

A bank account is the classic real-world example: you're never handed direct access to someone's balance variable. Instead the bank exposes actions — deposit, withdraw, check balance — each of which can enforce rules like "no negative balances." That's encapsulation: fields marked private, accessed only through public getters and setters.

BankAccount.java
public class BankAccount {
    private double balance;   // hidden — no direct outside access
 
    public double getBalance() {           // getter
        return balance;
    }
 
    public void deposit(double amount) {   // controlled write access
        if (amount > 0) balance += amount;
    }
 
    public void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
        } else {
            System.out.println("Withdrawal denied.");
        }
    }
}
Without encapsulation, any code anywhere could set balance = -9999 directly. The setter is where the rules live.

10 Inheritance

One class acquires the fields and methods of another using extends, letting you reuse and specialize behavior.

Single

One subclass, one superclass. Dog extends Animal.

Multilevel

A chain of inheritance. Puppy extends Dog extends Animal.

Hierarchical

Several subclasses share one superclass. Dog and Cat both extend Animal.

Inheritance.java
class Animal {
    void eat() {
        System.out.println("This animal eats food.");
    }
}
 
class Dog extends Animal {   // single inheritance
    void bark() {
        System.out.println("Woof!");
    }
}
 
class Puppy extends Dog {    // multilevel — Puppy gets eat() AND bark()
    void whine() {
        System.out.println("Whimper.");
    }
}
 
class Cat extends Animal {   // hierarchical — Dog and Cat share Animal
    void meow() {
        System.out.println("Meow!");
    }
}
Java doesn't allow a class to extends two classes at once — no multiple inheritance of classes. Interfaces fill that gap instead.

11 Polymorphism

"Many forms" — the same method name behaving differently depending on how it's called, or on which object calls it.

Compile-time (static) polymorphism. Multiple methods share a name in the same class but differ in parameter list. The compiler picks the right one based on the arguments you pass.

Overload.java
class Calculator {
    int add(int a, int b) {
        return a + b;
    }
    double add(double a, double b) {   // same name, different params
        return a + b;
    }
    int add(int a, int b, int c) {
        return a + b + c;
    }
}

Runtime (dynamic) polymorphism. A subclass redefines a method it inherited, using the exact same signature. Which version runs is decided at runtime, based on the object's actual type.

Override.java
class Animal {
    void makeSound() {
        System.out.println("Some generic animal sound");
    }
}
 
class Dog extends Animal {
    @Override
    void makeSound() {          // redefines the inherited method
        System.out.println("Woof!");
    }
}
 
// Animal a = new Dog(); a.makeSound(); -> prints "Woof!"

At a glance

OverloadingOverriding
ResolvedAt compile timeAt runtime
Classes involvedSame classParent and child class
SignatureMust differMust match exactly
PurposeOffer flexible ways to call similar logicCustomize inherited behavior

12 Abstraction

Exposing only what a user of a class needs to know, and hiding the implementation details behind it.

Abstract class

Can mix fully implemented methods with abstract (unimplemented) ones. A class can extend only one abstract class. Use it when subclasses share common state or partial behavior.

Interface

Defines a contract — method signatures with no implementation (aside from default methods). A class can implement many interfaces. Use it to define a capability unrelated classes can share.

Abstraction.java
abstract class Shape {
    abstract double area();       // no body — subclasses must implement it
 
    void describe() {              // shared, fully implemented
        System.out.println("This shape has area " + area());
    }
}
 
class Circle extends Shape {
    double radius = 3;
    @Override
    double area() {
        return Math.PI * radius * radius;
    }
}
 
interface Drivable {
    void drive();               // contract only
}
 
class Car implements Drivable {
    @Override
    public void drive() {
        System.out.println("Driving the car.");
    }
}

13 Exception Handling

Java forces you to plan for what happens when something goes wrong, instead of letting the program crash silently.

Exceptions.java
public class Exceptions {
 
    static int divide(int a, int b) throws ArithmeticException {
        if (b == 0) {
            throw new ArithmeticException("Cannot divide by zero");
        }
        return a / b;
    }
 
    public static void main(String[] args) {
        try {
            int result = divide(10, 0);
            System.out.println(result);
        } catch (ArithmeticException e) {
            System.out.println("Caught: " + e.getMessage());
        } finally {
            System.out.println("This runs whether or not an exception occurred.");
        }
    }
}
KeywordRole
tryWraps code that might throw an exception
catchHandles a specific exception type if one is thrown
finallyRuns regardless of whether an exception occurred — cleanup code
throwManually raises an exception instance
throwsDeclares that a method might raise an exception, in its signature

14 Collections Framework

A unified set of interfaces and classes for storing and manipulating groups of objects, instead of hand-rolling arrays everywhere.

List

Ordered, allows duplicates. ArrayList, LinkedList. Access by index.

Set

No duplicates allowed. HashSet, TreeSet. Good for uniqueness checks.

Map

Key-value pairs, unique keys. HashMap, TreeMap. Fast lookup by key.

Collections.java
import java.util.*;
 
List<String> names = new ArrayList<>();
names.add("Ada");
names.add("Grace");
 
Set<Integer> uniqueIds = new HashSet<>();
uniqueIds.add(101);
uniqueIds.add(101);   // ignored — duplicate
 
Map<String, Integer> ages = new HashMap<>();
ages.put("Ada", 36);
System.out.println(ages.get("Ada"));  // 36

15 Common Questions

A few things almost everyone asks in their first week.

public so the JVM (outside the class) can call it; static so it can run without creating an object first; void because it returns nothing to the operating system; and String[] args lets you pass command-line arguments in.
== compares references — whether two variables point to the exact same object in memory. .equals() compares content — whether two Strings hold the same characters. Almost always use .equals() for Strings.
Reach for an abstract class when related classes share common fields or partial implementation. Reach for an interface when you're describing a capability (like Comparable or Runnable) that unrelated classes might all need.
