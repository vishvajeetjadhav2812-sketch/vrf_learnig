HTML, CSS & JavaScript, from tags to interactivity.

The three languages that build everything you see in a browser. HTML gives a page its structure, CSS gives it appearance, and JavaScript gives it behavior. This guide moves in that order — structure, then style, then behavior — the same order a browser actually processes a page in.

LevelBeginner → Advanced
Reading time~70 min
TargetModern Browsers
01

How the Web Works

When you open a website, your browser requests a file from a server, receives back an HTML document, and reads it top to bottom to build a structure called the DOM (Document Object Model). CSS files attach styling rules to that structure, and JavaScript files attach behavior — they respond to clicks, fetch new data, and change what's on screen without reloading the page.

All three languages sit in the same file or are linked together: HTML is the skeleton, CSS is the skin, JavaScript is the nervous system. None of them "run" without the other two present in some form.

02

Tools You'll Need

You need three things to start: a text editor (VS Code is the standard choice), a modern browser (Chrome, Firefox, or Edge — each has built-in developer tools), and nothing else. No installation, no compiler, no server required to begin. Open your browser's DevTools with F12 or Ctrl+Shift+I to inspect any page's HTML, CSS, and console output live.

  • Save any file with a .html extension and double-click it to open it in a browser.
  • The Elements tab in DevTools shows live HTML and CSS.
  • The Console tab runs JavaScript and shows errors.
03

Document Structure

Every HTML page starts with the same skeleton. The <!DOCTYPE html> declaration tells the browser to use modern standards. Everything visible lives inside <body>; metadata, the page title, and linked files live inside <head>.

html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>My Page</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <h1>Hello, World!</h1>
    <script src="script.js"></script>
  </body>
</html>

The <script> tag is usually placed just before </body> so the page's content loads before JavaScript tries to touch it.

04

Elements & Attributes

An element is an opening tag, its content, and a closing tag: <p>text</p>. Some elements are "void" and never wrap content, like <img> or <br>. Attributes go inside the opening tag and configure the element — id, class, and style work on almost anything.

html
<p id="intro" class="muted large">
  Attributes configure an element.
</p>
<img src="cat.jpg" alt="A sleeping cat">

id must be unique on the page; class can be reused across many elements and is how CSS and JavaScript usually target groups of elements.

05

Text, Headings & Lists

Headings run from <h1> (most important) to <h6>, and should be used in order — one h1 per page, not chosen for font size. Lists come in two flavors: ordered (<ol>) and unordered (<ul>), both containing <li> items.

html
<h1>Main Title</h1>
<h2>Section Title</h2>
<ul>
  <li>First item</li>
  <li>Second item</li>
</ul>
06

Links, Images & Media

The anchor tag <a> creates links via its href attribute. Images use <img> with a required alt attribute for accessibility and for when the image fails to load. Video and audio have their own native tags with built-in controls.

html
<a href="https://example.com" target="_blank">Visit site</a>
<video src="clip.mp4" controls></video>
07

Tables

Tables are for tabular data only, never for page layout. <table> wraps rows (<tr>), which contain header cells (<th>) or data cells (<td>).

html
<table>
  <tr><th>Name</th><th>Score</th></tr>
  <tr><td>Asha</td><td>92</td></tr>
</table>
08

Forms & Input Fields

Forms collect user input. Every field needs a name attribute so its value is identifiable when submitted, and should be paired with a <label> for accessibility.

html
<form>
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">Send</button>
</form>
09

Semantic HTML & Accessibility

Semantic tags describe meaning, not just appearance: <header>, <nav>, <main>, <article>, <section>, and <footer> tell both browsers and screen readers what each part of the page is for, instead of relying on a generic <div> for everything.

  • Use one <main> per page for the primary content.
  • Give images meaningful alt text, not filenames.
  • Make sure interactive elements are reachable by keyboard (Tab key).
10

Selectors & Specificity

A CSS rule is a selector followed by declarations in braces. Selectors can target a tag, a class (.name), an id (#name), or a combination. When two rules conflict, the more specific selector wins; ids beat classes, and classes beat tag names.

css
p {
  color: #333;
}
.card h2 {
  font-weight: 700;
}
#hero {
  text-align: center;
}
11

The Box Model

Every element is a rectangular box made of four layers, from the inside out: content, padding, border, and margin. By default, width and height apply only to the content — setting box-sizing: border-box makes padding and border count inside that width instead, which is why almost every project sets it globally.

css
* {
  box-sizing: border-box;
}
.box {
  width: 200px;
  padding: 20px;
  border: 1px solid #ccc;
  margin: 16px;
}
12

Colors, Units & Typography

Colors can be named, hex (#7c3aed), or functional (rgb(), hsl()). For sizing, px is fixed, % is relative to a parent, and rem is relative to the root font size — rem is the standard choice for anything that should scale with user font-size preferences.

css
body {
  font-family: "Inter", sans-serif;
  font-size: 1rem;
  line-height: 1.6;
  color: hsl(240, 10%, 15%);
}
13

Flexbox

Flexbox lays out children in a single row or column and distributes space between them. Set display: flex on the parent; justify-content controls alignment along the main axis, align-items along the cross axis.

css
.row {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 12px;
}
14

CSS Grid

Grid lays elements out in two dimensions at once — rows and columns together. grid-template-columns defines the column tracks; fr units split remaining space proportionally.

css
.grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
15

Positioning & Display

position: relative moves an element relative to where it would normally sit; absolute removes it from normal flow and positions it against its nearest positioned ancestor; fixed pins it to the viewport, which is how sticky headers and modals are built.

css
.tooltip {
  position: absolute;
  top: 100%;
  left: 0;
}
16

Responsive Design

Media queries apply rules only when the viewport matches a condition, usually a maximum width, letting the same page rearrange itself for phones, tablets, and desktops.

css
.grid {
  grid-template-columns: repeat(3, 1fr);
}
/* stack into one column below 700px */
@media (max-width: 700px) {
  .grid {
    grid-template-columns: 1fr;
  }
}
17

Transitions & Animations

transition smoothly animates a property change (like on hover). @keyframes defines a multi-step animation that can loop or run once, attached to an element via animation.

css
.btn {
  transition: background-color 0.2s ease;
}
.btn:hover {
  background-color: #7c3aed;
}
18

Variables & Data Types

Variables are declared with let (can change) or const (can't be reassigned) — var is legacy and best avoided. JavaScript's core types are string, number, boolean, null, undefined, object, and array.

js
const name = "Asha";
let age = 28;
const isStudent = true;
let score = null; // intentionally empty
19

Operators & Control Flow

Comparisons should use === and !== (strict equality), which check type as well as value, unlike ==. if / else if / else branches on conditions; for and while repeat work.

js
if (score >= 90) {
  console.log("Grade A");
} else if (score >= 70) {
  console.log("Grade B");
} else {
  console.log("Keep going");
}
 
for (let i = 0; i < 5; i++) {
  console.log(i);
}
20

Functions & Scope

A function packages reusable logic. Variables declared with let/const only exist inside the block { } they're declared in — this is called block scope, and it's why a variable created inside an if statement isn't visible outside it.

js
function greet(name) {
  return `Hello, ${name}!`;
}
 
console.log(greet("World")); // "Hello, World!"
21

Arrays & Objects

Arrays hold ordered lists; objects hold key–value pairs. Array methods like map, filter, and reduce transform data without writing manual loops, and are the backbone of most modern JavaScript.

js
const user = { name: "Asha", age: 28 };
const scores = [70, 85, 92];
 
const passed = scores.filter(s => s >= 75);
const doubled = scores.map(s => s * 2);
22

DOM Manipulation

The DOM is the live, in-memory version of your HTML. JavaScript can select elements and change their content, attributes, or classes, and the browser repaints the page instantly.

js
const title = document.querySelector("#title");
title.textContent = "Updated!";
title.classList.add("highlight");
23

Events

Events let JavaScript react to user actions — clicks, key presses, form submissions. addEventListener attaches a function that runs whenever that event fires.

js
const btn = document.querySelector("button");
btn.addEventListener("click", () => {
  console.log("Clicked!");
});
24

Modern JS (ES6+)

Arrow functions shorten function syntax and don't rebind this. Destructuring pulls values straight out of arrays or objects. Template literals embed variables directly inside strings using backticks.

js
const add = (a, b) => a + b;
const { name, age } = user;
const [first, second] = scores;
console.log(`${name} is ${age}`);
25

Promises, Async/Await & Fetch

A Promise represents a value that isn't ready yet — like data from a network request. async / await lets you write asynchronous code that reads top-to-bottom instead of nesting callbacks. fetch is the built-in way to call an API.

js
async function getUser(id) {
  const res = await fetch(`/api/users/${id}`);
  const data = await res.json();
  return data;
}
26

Classes & OOP

Classes are templates for creating objects with shared structure and behavior. The constructor runs when a new instance is created; methods defined on the class are shared by every instance.

js
class User {
  constructor(name) {
    this.name = name;
  }
  greet() {
    return `Hi, I'm ${this.name}`;
  }
}
 
const u = new User("Asha");
27

Storage & Error Handling

localStorage persists small amounts of data in the browser between visits, always as strings — objects need JSON.stringify and JSON.parse. try / catch stops an error from crashing the whole script.

js
localStorage.setItem("user", JSON.stringify(user));
 
try {
  const saved = JSON.parse(localStorage.getItem("user"));
} catch (err) {
  console.error("Couldn't read saved data", err);
}
