C#, from syntax to the CLR.

C# pairs the safety and structure of a statically typed, garbage-collected language with syntax that keeps evolving to stay expressive — pattern matching, records, and top-level statements all trimmed away boilerplate that used to be mandatory. This guide moves in the order you'll actually use it: syntax, objects, then the runtime and modern features once the fundamentals are second nature.

Level Beginner → Intermediate Reading time ~45 min Target .NET 8 / C# 12 examples

01 What is C# & .NET?

A modern, object-oriented language built by Microsoft specifically to run on a managed runtime — and the runtime, not just the language, is a huge part of the story.

C# was released in 2000, led by Anders Hejlsberg, as the flagship language for Microsoft's new .NET platform. Early .NET was Windows-only and closed-source; that changed dramatically in 2016 with .NET Core, an open-source, cross-platform rewrite that eventually became simply .NET (5, 6, 7, 8...). Today C# runs natively on Windows, macOS, and Linux, and powers everything from ASP.NET web APIs to Unity games to mobile apps via .NET MAUI.

Core features

Object-Oriented

Built around classes, interfaces, and inheritance, with first-class support for modern functional patterns too.

Type-Safe

The compiler catches type mismatches before your code ever runs, sharply reducing a whole class of runtime bugs.

Cross-Platform

Modern .NET runs the same C# code on Windows, macOS, and Linux without modification.

Garbage Collected

The CLR reclaims memory for objects you no longer reference — no manual free() calls required.

Strongly Typed

Every variable has a fixed type, whether declared explicitly or inferred with var.

Constantly Evolving

Nearly every yearly C# release adds syntax that removes boilerplate — records and top-level statements are recent examples.

02 How C# Code Actually Runs

C# doesn't compile straight to machine code — it goes through an intermediate step that's the whole reason .NET can be cross-platform.

1. Source (.cs)

The C# code you write.

2. CIL

The C# compiler (Roslyn) produces Common Intermediate Language — a platform-independent bytecode, packaged in a .dll/.exe.

3. JIT Compilation

At runtime, the CLR's Just-In-Time compiler translates CIL into native machine code for the current CPU.

4. Native Execution

The OS runs that native code directly, at full hardware speed.

This is conceptually close to Java's bytecode + JVM model — the difference is the CLR JIT-compiles per method as it's first called, rather than interpreting every instruction, which is why .NET performance is often close to natively compiled languages.

04 Anatomy of a C# Program

Modern C# lets you skip almost all the ceremony older versions required.

Program.cs
using System;                     // brings in the System namespace

namespace MyApp
{
    class Program
    {
        static void Main(string[] args)   // entry point
        {
            Console.WriteLine("Program starts here.");
        }
    }
}
Program.cs
using System;

Console.WriteLine("Program starts here.");   // no class or Main needed -- the compiler generates them for you

Both compile to the exact same thing. Top-level statements are ideal for small programs, scripts, and learning; larger projects still tend to use the classic namespace / class structure to organize code across files.

05 Data Types

The single most important distinction in C#'s type system: where a value actually lives in memory.

Value types

Stored directly on the stack (or inline in the containing object). Assigning one copies the value. Includes int, double, bool, struct, enum.

Reference types

Stored on the heap; the variable holds a reference (pointer) to it. Assigning one copies the reference, not the data. Includes class, string, array, interface.

types.cs
int a = 10;
int b = a;      // b gets a COPY of 10 -- changing a won't affect b

int? maybeAge = null;      // nullable value type -- the ? allows null for a normally non-nullable type
if (maybeAge.HasValue)
{
    Console.WriteLine(maybeAge.Value);
}

int safeAge = maybeAge ?? 0;   // null-coalescing -- falls back to 0 if null

06 Variables, Constants & Scope

C# gives you two flavors of "unchangeable" — and they mean different things.

const_vs_readonly.cs
class Circle
{
    public const double Pi = 3.14159;      // fixed at compile time, shared across all instances
    public readonly double Radius;         // set once, at construction -- can differ per instance

    public Circle(double radius)
    {
        Radius = radius;              // legal here, inside the constructor
    }
}
const must be known at compile time and is implicitly static. readonly can be assigned at runtime — but only inside the constructor — which makes it useful when the value depends on a constructor argument.

07 Input / Output

String interpolation replaced most of the old string-formatting boilerplate with something far more readable.

io.cs
Console.Write("Enter your name: ");
string? name = Console.ReadLine();     // ReadLine() can return null

Console.Write("Enter your age: ");
int age = int.Parse(Console.ReadLine()!);

Console.WriteLine($"Hi {name}, in 5 years you'll be {age + 5}.");   // string interpolation

The $ before a string turns it into an interpolated string — anything inside {} is evaluated and inserted directly, replacing older patterns like string.Format().

08 Operators & Control Flow

C# switch expressions bring real pattern matching, going far beyond a simple value comparison.

control_flow.cs
int score = 76;

if (score >= 90) Console.WriteLine("Grade: A");
else if (score >= 75) Console.WriteLine("Grade: B");
else Console.WriteLine("Grade: C or below");

// modern switch EXPRESSION -- evaluates to a value, no break needed
string grade = score switch
{
    >= 90 => "A",
    >= 75 => "B",
    >= 60 => "C",
    _   => "F"          // _ is the discard pattern -- matches anything else
};

foreach (var n in new[] { 1, 2, 3 })
{
    if (n == 2) continue;
    Console.WriteLine(n);
}

09 Two Complete Programs

The smallest possible C# program, and an interactive grade calculator that ties I/O, loops, and switch expressions together.

Hello, World

HelloWorld.cs
Console.WriteLine("Hello, World!");

Student Grade Calculator

GradeCalculator.cs
using System;
using System.Collections.Generic;

var scores = new List<int>();
Console.WriteLine("Enter scores one at a time. Type 'done' to finish.");

while (true)
{
    Console.Write("Score: ");
    string? input = Console.ReadLine();

    if (input?.ToLower() == "done") break;

    if (int.TryParse(input, out int score))
    {
        scores.Add(score);
    }
    else
    {
        Console.WriteLine("Not a valid number, try again.");
    }
}

if (scores.Count == 0)
{
    Console.WriteLine("No scores entered.");
    return;
}

double average = 0;
foreach (var s in scores) average += s;
average /= scores.Count;

string letter = average switch
{
    >= 90 => "A",
    >= 75 => "B",
    >= 60 => "C",
    _   => "F"
};

Console.WriteLine($"Average: {average:F2}  |  Grade: {letter}");

10 Classes & Objects

Constructors set up an object's initial state; object initializers offer a shorter alternative for simple cases.

Car.cs
public class Car
{
    public string Color { get; set; }
    public int Speed { get; private set; }

    public Car(string color)         // constructor
    {
        Color = color;
        Speed = 0;
    }

    public void Accelerate(int amount)
    {
        Speed += amount;
        Console.WriteLine($"{Color} car now going {Speed} km/h");
    }

    ~Car()                          // destructor / finalizer -- rarely needed, GC handles cleanup
    {
        // runs before the GC reclaims this object's memory
    }
}

var mine = new Car("Red");
mine.Accelerate(40);

// object initializer -- sets public properties inline, no constructor args needed
var yours = new Car("Blue") { Speed = 10 };
A destructor (finalizer) in C# is not deterministic — you don't control exactly when it runs. For deterministic cleanup (closing files, releasing handles), implement IDisposable instead — covered in the Memory Management section.

12 Properties

Properties look like fields from the outside but run code — a getter and setter — under the hood.

properties.cs
public class Product
{
    public string Name { get; set; } = "";   // auto-implemented -- compiler generates the backing field

    private decimal _price;
    public decimal Price               // full get/set accessor -- with validation logic
    {
        get => _price;
        set
        {
            if (value < 0) throw new ArgumentException("Price can't be negative");
            _price = value;
        }
    }

    public string Sku { get; init; } = "";    // init-only -- settable only during object creation
}

var item = new Product { Name = "Widget", Price = 9.99m, Sku = "W-100" };
// item.Sku = "W-200";   -> compile error: init-only, can't be changed after creation

13 The Four Pillars of OOP

Abstraction, encapsulation, inheritance, and polymorphism — the vocabulary every OOP language builds on.

Abstraction

Exposing only what's necessary to use something, hiding implementation details behind interfaces or abstract classes.

Encapsulation

Bundling data with the methods that operate on it, restricting direct access via access modifiers and properties.

Inheritance

inheritance.cs
public class Animal
{
    public string Name { get; }
    public Animal(string name) => Name = name;

    public virtual void Speak() => Console.WriteLine("Some generic animal sound");
}

public class Dog : Animal
{
    public Dog(string name) : base(name) { }     // base() calls the parent constructor

    public override void Speak()          // override -- replaces the virtual method
    {
        Console.WriteLine($"{Name} says Woof!");
    }
}

Polymorphism: override vs new

override_vs_new.cs
Animal a = new Dog("Rex");
a.Speak();          // "Rex says Woof!" -- override respects the ACTUAL runtime type

// if Dog used "new void Speak()" instead of "override" it would HIDE the parent
// method rather than replace it -- calling a.Speak() through an Animal reference
// would then print the parent's generic sound, since 'new' is resolved by the
// declared (compile-time) type, not the actual object.

14 Interfaces vs Abstract Classes

Both define a contract a class must fulfill, but they solve different problems.

Abstract class

Can hold state (fields), constructors, and fully implemented methods alongside abstract ones. A class can inherit from only one.

Interface

Defines a contract — method signatures (plus optional default implementations in modern C#). A class can implement many interfaces at once.

Abstract classInterface
Multiple inheritanceNo — only one base classYes — a class can implement many
Fields / stateAllowedNot allowed (properties only, no backing fields)
ConstructorsAllowedNot allowed
Use whenRelated classes share common state or partial behaviorUnrelated classes need to share a capability/contract
interfaces.cs
public interface IDrivable
{
    void Drive();
}

public abstract class Shape
{
    public abstract double Area();      // no body -- subclasses must implement it

    public void Describe()             // shared, fully implemented
        => Console.WriteLine($"Area is {Area()}");
}

public class Circle : Shape, IDrivable      // one base class, plus interfaces, separated by commas
{
    public double Radius { get; set; }
    public override double Area() => Math.PI * Radius * Radius;
    public void Drive() => Console.WriteLine("Rolling along!");
}

15 Collections

The generic collection types that replace nearly every use case for a raw array.

List<T>

Ordered, resizable, allows duplicates. The default choice for most sequences.

Dictionary<TKey, TValue>

Key-value pairs with unique keys and fast lookup by key.

HashSet<T>

Unique, unordered items — great for de-duplication and fast membership checks.

IEnumerable<T>

The base interface nearly every collection implements — anything you can foreach over.

collections.cs
var names = new List<string> { "Ada", "Grace" };
names.Add("Linus");

var ages = new Dictionary<string, int> { ["Ada"] = 36 };
Console.WriteLine(ages["Ada"]);       // 36

var uniqueIds = new HashSet<int> { 1, 1, 2 };  // { 1, 2 } -- duplicate silently dropped

16 LINQ

Language Integrated Query lets you filter, transform, and aggregate collections declaratively, in two equivalent syntaxes.

linq_method.cs
using System.Linq;

var numbers = new[] { 4, 8, 15, 16, 23, 42 };

var result = numbers
    .Where(n => n > 10)              // filter
    .Select(n => n * 2)              // transform
    .OrderByDescending(n => n)     // sort
    .ToList();
// [84, 46, 32, 30]

var grouped = numbers.GroupBy(n => n % 2 == 0 ? "even" : "odd");
foreach (var g in grouped)
    Console.WriteLine($"{g.Key}: {string.Join(",", g)}");
linq_query.cs
using System.Linq;

var numbers = new[] { 4, 8, 15, 16, 23, 42 };

var result =
    from n in numbers
    where n > 10
    orderby n descending
    select n * 2;
// same result as the method-syntax version, SQL-like reading order

Both compile to the same underlying calls — method syntax is more common in real-world code because it composes more easily and covers operators query syntax doesn't have direct keywords for.

17 Delegates, Events & Lambda Expressions

A delegate is a type-safe reference to a method — the foundation events and LINQ are both built on.

delegates_events.cs
public delegate void Notify(string message);   // defines a method "shape"

public class Alarm
{
    public event Notify? OnTrigger;      // an event -- a controlled, publish/subscribe delegate

    public void Trigger()
    {
        OnTrigger?.Invoke("Alarm triggered!");   // ?. -- only invoke if someone subscribed
    }
}

var alarm = new Alarm();
alarm.OnTrigger += msg => Console.WriteLine($"Received: {msg}");  // lambda subscribed as handler
alarm.Trigger();

// standalone lambda expressions, without an event:
Func<int, int> square = x => x * x;
Console.WriteLine(square(5));         // 25

18 Generics

Write a class or method once, and let it work with any type — safely, with full compile-time type checking.

generics.cs
public class Box<T> where T : class       // constraint -- T must be a reference type
{
    private T? _item;
    public void Store(T item) => _item = item;
    public T? Retrieve() => _item;
}

public static T Max<T>(T a, T b) where T : IComparable<T>   // generic method with an interface constraint
{
    return a.CompareTo(b) > 0 ? a : b;
}

var box = new Box<string>();
box.Store("hello");

Console.WriteLine(Max(10, 25));       // 25
Common constraints: where T : class (reference type), where T : struct (value type), where T : new() (must have a parameterless constructor), where T : SomeInterface.

19 Memory Management

The CLR handles memory for you — but understanding how gives you real control over performance.

Value types (int, struct, local variables) live on the fast, automatically-managed stack. Reference types (class instances) live on the heap, and the variable on the stack just holds a pointer to that heap memory.

stack_vs_heap.cs
int x = 5;                    // x lives directly on the stack
var obj = new object();       // obj (stack) holds a pointer to data on the heap

The .NET Garbage Collector uses a generational model, on the assumption that most objects die young:

  • Gen 0 — newly created objects. Collected frequently and fast.
  • Gen 1 — objects that survived one Gen 0 collection. A buffer between short and long-lived.
  • Gen 2 — long-lived objects. Collected rarely, since scanning it is expensive.

An object gets "promoted" a generation each time it survives a collection, which is why long-lived caches and static collections put more pressure on the GC than short-lived local variables.

Some resources — file handles, database connections, network sockets — aren't managed memory and need explicit, deterministic cleanup. That's what IDisposable and using are for.

idisposable.cs
public class FileLogger : IDisposable
{
    private StreamWriter _writer = new("log.txt");

    public void Log(string msg) => _writer.WriteLine(msg);

    public void Dispose()          // releases the unmanaged file handle
    {
        _writer.Dispose();
    }
}

using (var logger = new FileLogger())   // Dispose() called automatically at the end of this block
{
    logger.Log("Started");
}   // -- even if an exception was thrown inside the block

20 Async / Await

Asynchronous code lets a thread stay free to do other work while waiting on something slow — I/O, a network call, a file read.

async_await.cs
using System.Net.Http;

public static async Task<string> FetchDataAsync(string url)
{
    using var client = new HttpClient();
    string result = await client.GetStringAsync(url);   // frees the thread while waiting on the network
    return result;
}

public static async Task Main()
{
    string data = await FetchDataAsync("https://example.com");
    Console.WriteLine($"Got {data.Length} characters");
}
Avoiding deadlocks: never call .Result or .Wait() on a Task from synchronous code that also owns the same synchronization context (like a UI thread) — it can block forever waiting on itself. Use await all the way up the call chain instead.

Task represents an async operation with no return value; Task<T> represents one that eventually produces a T. Marking a method async lets you use await inside it, and the compiler rewrites it into a state machine behind the scenes.

21 Exception Handling

Structured error handling, plus the ability to define your own exception types for domain-specific failures.

exceptions.cs
public class InsufficientFundsException : Exception
{
    public InsufficientFundsException(string message) : base(message) { }
}

public static void Withdraw(decimal balance, decimal amount)
{
    if (amount > balance)
        throw new InsufficientFundsException("Not enough balance.");
}

try
{
    Withdraw(100, 150);
}
catch (InsufficientFundsException ex)
{
    Console.WriteLine($"Caught: {ex.Message}");
}
catch (Exception ex)
{
    Console.WriteLine($"Unexpected: {ex.Message}");
}
finally
{
    Console.WriteLine("Withdrawal attempt finished.");   // always runs
}

22 Modern C# Innovations

A handful of recent features that meaningfully changed how everyday C# code looks.

Records & Tuples

records_tuples.cs
public record Point(int X, int Y);      // immutable by default, value-based equality auto-generated

var p1 = new Point(1, 2);
var p2 = new Point(1, 2);
Console.WriteLine(p1 == p2);      // True -- records compare by VALUE, not by reference

var p3 = p1 with { Y = 10 };     // "with" -- creates a copy with one property changed

(string Name, int Age) person = ("Ada", 36);   // tuple with named elements
Console.WriteLine($"{person.Name} is {person.Age}");

Pattern Matching & Null-Coalescing

patterns_nullcoalescing.cs
object shape = 5;

if (shape is int n and > 0)          // pattern matching -- type check + binding + condition
{
    Console.WriteLine($"Positive int: {n}");
}

string? username = null;
string display = username ?? "Guest";   // ?? -- use "Guest" only if username is null
username ??= "anonymous";               // ??= -- assign only if currently null

23 File I/O

The System.IO.File class exposes async versions of nearly every operation, keeping the calling thread free while disk I/O happens.

file_io_async.cs
using System.IO;

public static async Task RunAsync()
{
    await File.WriteAllTextAsync("notes.txt", "C# makes async I/O simple.\n");

    string contents = await File.ReadAllTextAsync("notes.txt");
    Console.WriteLine(contents);

    await File.AppendAllTextAsync("notes.txt", "Another line.\n");
}
These static helpers cover most needs; for large files or streaming, use FileStream with await using so the stream is disposed asynchronously too.
